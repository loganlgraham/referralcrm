# Agent Memory

## Learned User Preferences

- Plan-then-implement workflow: plans live under `.cursor/plans/`, todos are auto-created, agent implements without editing the plan file and works todos sequentially until done; short directives like "implement", "proceed", "do it", "yes", "approved" mean execute the last proposal without re-confirming.
- "Commit and push" requests stage/commit/push everything without extra prompting; default target is the current working branch, use `main` or a fresh branch only when the user explicitly says so (and include incidental edits like `.cursor/` debug artifacts when the user says "yes include those too").
- Format phone numbers as `###-###-####` everywhere (imports, UI, stored values) and prices as `$###,###,###` with commas in toasts and UI.
- Default new task due times to 8:00 AM America/Denver (MT) and keep timezone-aware bucketing for Urgent/Upcoming/Overdue.
- Use plain, layman-friendly wording in user-facing UI text and explanations; avoid exposing internal field names like `usedAssignedAgent` or `usedAfc` in copy, and translate technical plans into concrete business/user impact when the user asks what they mean. Lost reasons and agent-created status labels must not name or emphasize the MC or Agent — agent-created referrals use the same status names as admin-created ones, just measured differently.
- Keep dashboards lean: prefer one consolidated leaderboard/table, or a combined summary card paired side-by-side with a per-MC leaderboard table, over stacking many small metric cards (e.g. fold "Deals pushed back" + "Pushback rate" into a single `PushbackSummaryCard` next to `McPushbackLeaderboardTable`); remove cards when asked rather than hiding them, and favor clickable drilldowns that open filtered tables for just the referenced metric/status cohort.
- Expect screenshots (pasted into `assets/`) as the primary feedback channel for UI issues; treat them as authoritative on layout/visual intent. When a bug manifests only in the browser (stuck progress bars, stale state after nav, etc.), instrument first with `console` logging around the suspected handler, ask the user to reproduce, then remove all instrumentation before final commit. Hide the header logo on mobile; keep admin toasts fully visible and centered on small screens.
- Respect the `no-inline-imports` and TypeScript exhaustive-switch workspace rules when editing.
- When a fix surfaces pre-existing test/CI/build failures in adjacent areas, fix them in-line in the same pass (user routinely says "fix those two" for collateral failures); known non-blocking noise to call out but keep shipping: `pnpm lint` fails on `next lint` vs ESLint v9 CLI incompat, and top-level `tsc` errors under `tests/` (missing `@jest/globals`/`@types/supertest`) — neither blocks Vercel deploys since Next only typechecks `src/`.
- For admin email reports, default to multi-recipient (comma-separated), optional CSV attachment plus a standalone CSV download button, and recurring cadences (daily / weekly Mon / monthly 1st at 7am MT) backed by a `ScheduledReport` cron. Restyle all outbound mail to `docs/DESIGN.md` with publicly hosted brand assets (local/relative logos show as broken images); Send Fee Breakdown uses the AHA office address 3190 South Vaughn Way, Suite 550 Aurora, CO 80014 and attaches the current W9.
- When a metric can accept historical input (e.g., referrals imported with a prior `referralDate`), anchor durations on the earliest meaningful date (`min(referralDate, createdAt)`) rather than gating on status-change timestamps so retro-dated imports count toward elapsed-time KPIs.
- Keep role surfaces distinct: email-MC on notes defaults only for the agent role (admin notes stay off); the activity timeline is admin-only but must log agent, admin, and MC actions; an agent's "Waiting on you" list shows only unanswered admin auto-update request emails and hides a referral if the agent updated it in the last 3 days.

## Learned Workspace Facts

- Next.js 14 App Router CRM (`referralcrm`, repo `loganlgraham/referralcrm`) deployed on Vercel at `referrio.app` with `engines.node` `24.x`; uses MongoDB via Mongoose, NextAuth, Radix UI, TanStack Table, and `lucide-react`. Brand kit lives in `src/components/brand/` plus `docs/DESIGN.md` (Manrope via `next/font`).
- Tests: `pnpm test` runs lint + Jest unit (`jest.config.ts`); API tests via `pnpm test:api` (runs with `TZ=America/Denver`); e2e via Playwright (`pnpm test:e2e`); seed with `pnpm seed`. Jest config requires `testEnvironmentOptions.customExportConditions: ['node', 'node-addons']` (for `bson` CJS resolution) and a default `MONGODB_URI` in `jest.setup.ts`; both `/tests/e2e/` and `<rootDir>/e2e/` are in `testPathIgnorePatterns`. Pure helpers (e.g. `merge-closed-status-query.ts`) should be extracted into mongoose/auth-free modules to stay unit-testable.
- Core domain entities live in `src/models/`: `referral.ts`, `lender.ts` (LenderMC), `user.ts` (roles include `mortgage-consultant` and admin), plus deals/payments and tasks; the embedded `referralNoteSchema` `author` ObjectId is optional so system imports can write notes without a user id. Distinguish agent-created vs admin-created referrals: agent "Introduce a client to AFC" is always a buyer (no client-type or current-address fields) and should send a thankful received/paired confirmation to the agent.
- Inbound referral intake: `src/app/api/inbound-email/route.ts` receives Resend webhooks signed by Svix (`svix-*` headers, `RESEND_WEBHOOK_SECRET` / inbound signing secret); addresses use `import+<mailbox>@referrio.app` (e.g., `import+aha`, `import+ahaoos`), but Gmail-forwarded kvCORE emails can preserve the original visible `To`, so routing tries `to` first then exact subject fallbacks: `Add Contact` → AHA and `AHA Out of State Agent Needed` → AHA_OOS. Partner emails frequently embed literal `<br>`/`</p>`/`</div>`/`</tr>`/`</li>`/`</h1-6>`/`&nbsp;` tags inside `email.text`, so `normalizeInboundTextBreaks()` runs at the single `extractLabeledFields(email.text)` call site to turn them into real newlines before labeled parsing; loan numbers are capped to the first 11 digits to guard against concatenated trailing values like "+2%" or "30 Year". Parsed `Notes:` is seeded into `notes[]` as `{ authorRole: 'system', authorName: 'Inbound Email Import', content: cleanedNotes }` (the detail-page Notes section reads `notes[]`, not `initialNotes`). Parser coverage includes nested labels `So: (Source): ...`, `En: (Endorser): ...`, and `LoanType: ...`; missing/malformed fields leave `source`/`endorser`/`loanType` blank. Email-imported New Lead referrals should still generate the admin task Assign Agent → Move to paired.
- MC matching reads the `Source:` field as `{FirstName}{LastInitial}` (e.g., `KarimL`, `UmedY`); aliases normalize `ChristopherL` → `ChrisL`, `JasonCr` → `JasonC`, and `NebiyuA` → `NebA` / Neb Ayalew, and the free-text fallback in `src/lib/server/mc-matcher.ts` scans one- or two-letter suffix tokens, dedupes, and intersects with real MC tokens — multiple distinct MC matches log `ambiguous_free_text_match` and skip auto-assign. OpenAI (`openai` package, `OPENAI_API_KEY`) remains the field-extraction fallback when the regex/field parser cannot extract required fields.
- AFC = America's First Choice (preferred lender). Deal flags `usedAfc` and `usedAssignedAgent` drive most MC KPIs; sell-side deals are generally excluded from MC-email and AFC rules (buy-side only). `referralFeeBasisPoints === 0` is a valid explicit 0% referral fee and must not fall back to default tier percentages in API/UI/referral calculations. Agent-created referrals sent to AFC skip commission/referral-fee inputs at under contract (do not show explanatory "no fee" copy); admin-assigned referrals still collect fees.
- Agent-note default-to-email-MC rule applies only to the agent role: ON when the referral has a buy-side deal with `usedAfc=true` or has no deal/payment yet; OFF when there is a buy-side deal with `usedAfc=false`. Admin notes must not default email-MC to true.
- Referral/deal statuses include: under contract, closed, payment sent, payment received, terminated (with reason e.g. "Financing"); closed/payment-sent/payment-received must be filtered out of at-risk lists. Terminating a deal (agent or admin) prompts a still-shopping toast: yes → Active Lead, no → Lost with a role-neutral reason, maybe → In Communication. Per-side statuses live on `buyStatus`/`sellStatus` and aggregate via `deriveReferralStatusFromSides` in `src/lib/server/referral-sides.ts` (`clientType: 'Seller'` returns sellStatus first, `'Buyer'` returns buyStatus first, `'Both'` uses cross-side priority). `updateStatusSchema` in `src/utils/validators.ts` does NOT gate `Lost` behind a prior `Paired` step — any status can transition to Lost. For non-Both referrals the `StatusChanger` in `src/components/referrals/referral-header.tsx` must pass `primarySide` (derived from `clientType`) rather than the drift-prone `dealSide` DB field; `/api/referrals/[id]/status` also coerces `requestSide` to `'sell'`/`'buy'` from `clientType` so a sell-side `Lost` actually lands on `sellStatus`. Agent-loss KPIs attribute by lost reason, not stage, so paired→lost does not penalize an agent who never reached the borrower.
- MC dashboard (admin role) centers on: MC Composite KPI Leaderboard (relative scoring vs top performer), AFC Loss Risk Call List (buyers in Active Lead or In Communication only — not under contract — capped scrollable after 10 rows), a full-width `TransferTimingCard` comparing before- vs after-pre-approval transfer close rates from `stageOnTransferSummary`, and a combined `PushbackSummaryCard` + `McPushbackLeaderboardTable` (per-MC count + rate) side-by-side; KPIs include close rate, close-rate with assigned agent, outside-lender loss rate, pushed-back closings + avg push-back days, NPS (medium weight), financing terminations, and total revenue (high weight). Reassigning a referral to a new MC is not a transfer. Main-dashboard conversion funnel semantics are cumulative (stage N counts referrals whose max stage reached is >= N), with Lost/Terminated treated as branch outcomes rather than core funnel rows.
- Closed-deal counts and revenue are payment-driven (`Payment.status ∈ {closed, payment_sent, paid}` + `receivedAmountCents`), never `referral.status === 'Closed'`; geography sections must filter to payments with `receivedAmountCents > 0` to avoid "Unknown" bloat. Network bucketing marks `Unpaired` only when no MC is assigned; paired referrals roll up to AHA / AHA OOS / AGIT (network label was renamed from AFC → AGIT in the dashboard report breakdown — keep AGIT consistent across exec summary, breakdown, and settings copy) via the MC's `ahaDesignation`/network.
- Dashboard metric reports share `buildDashboardReport()` in `src/lib/server/dashboard-report.ts`, which calls `/api/dashboard` server-side (cookie-forwarded) for canonical KPIs so email, CSV download (`/api/admin/dashboard-report/csv`), and recurring delivery all match the live dashboard; on Vercel it prefers in-process dashboard route invocation (with HTTP fallback) to avoid self-fetch failures. `DashboardReportTimeframe` supports `This week` / `This month` / `Last week` / `Last month` / `Last 90 days` / `Year to date` / `All` / `Custom export window` (Last* options map to the API's `custom` key via date-fns `subWeeks`/`subMonths`). Executive summary splits Entered Under Contract into `(used assigned agent)` + AHA/AHA OOS/AGIT sub-rows + `(total)`, resolved by `countReferralsEnteredUnderContract` joining `Payment.agentId` → fallback `referral.assignedAgent` → `Agent.ahaDesignation`. Pushback KPIs scope to non-terminated deals via `resolvePushbackMetricsInTimeframe()` in `src/lib/server/pushback-metrics.ts` (pushback event `timestamp`, fallback `updatedAt`) and expose `pushbackSummary.byMc`. Communicating→Under Contract SLA in `src/utils/sla-insights.ts` always anchors on `min(referralDate, createdAt)` via `resolveEarliestStart`, so historical `referralDate` imports extend the elapsed metric. Recurring delivery is backed by the `ScheduledReport` model + `/api/cron/scheduled-reports`, registered hourly in `vercel.json`, filtered to 7am America/Denver, authed via `Authorization: Bearer ${CRON_SECRET}`.
- Known client/build gotchas: `NavigationProgress` (`src/components/layout/navigation-progress.tsx`) `handleClick` must bail on `event.defaultPrevented`, non-left `button`, any modifier key, and anchors with a non-`_self` `target` or Ctrl/Cmd/Shift/middle-click new-tab opens leave the bar stuck — and do NOT call `start()` from `popstate` (App Router hydrates cached pages synchronously so the pathname effect finishes the bar). Vercel build typechecks `src/` only (not `tests/`), but `export { x } from '...'` doesn't bring `x` into local scope so a re-export without a matching top-of-file `import` breaks `next build`. Respect per-scope helper signatures (e.g. `isWithinTimeframe()` inside `src/app/api/dashboard/route.ts` is single-arg), and prefer strict null guards (`value !== null && !Number.isNaN(value.getTime())`) over `Boolean(value)` for `Date | null`. Automated agent reminder email lives in `src/lib/server/auto-update-reminders.ts` (subject `Scheduled Update: {BuyerName}`, sections Buyer Info → Mortgage Consultant at AFC → Agent Relationship Coordinator hardcoded Kristen Truong, `View Referral` CTA); deep links in outbound mail must use `referrio.app`, not localhost.
